# Real City Lab：好きな範囲を選び、道路閉鎖の影響を見る

このガイドは、2026年10月16日の範囲選択・地域データ取得・閉鎖操作の改善を説明します。道路や施設の位置はOpenStreetMap、交通需要や容量はモデル上の値です。避難経路の安全性や実際の災害被害を予測するサービスではありません。

## 1. アプリの地図で範囲を選ぶ

1. ヘッダーの **Real City Lab** を開きます。
2. 地図を移動・拡大して対象地域を表示し、**いま見えている範囲を選ぶ / Use visible map area** を押します。
3. 青い枠の四隅をドラッグして調整します。**地図で範囲を選ぶ / Select area on map** で対角の2点を順に押しても選択できます。
4. 面積を確認し、**交通ネットワークを構築 / Build Mobility Network** を押します。

サンプル都市だけに限定されているわけではありません。地図を自由に移動できます。座標が分かる場合は `緯度, 経度` を入力して移動できます。OpenStreetMapの地図URLも受け付けますが、外部サイトを開くことは必須ではありません。この入力は位置の形式を端末内で読み取り、地名検索サービスには送信しません。地名による検索は未実装です。

| 選択面積          | 取り込む道路と制約                                                             |
| ----------------- | ------------------------------------------------------------------------------ |
| 1〜10 km²         | 詳細な道路解析の推奨範囲。住宅道路などを含みます。                             |
| 25 km²以下        | 詳細道路を対象にしますが、道路が多すぎる場合は同じ枠の主要道路へ切り替えます。 |
| 25 km²超〜100 km² | 広域の主要道路ネットワークとして解析します。住宅道路・細街路は含みません。     |
| 100 km²超         | 取得前に停止します。枠を小さくしてください。                                   |

広域モードには motorway、trunk、primary、secondary、tertiary と接続道路を含みます。選択した枠を黙って別の地域に変えたり、自動で縮めたりはしません。主要道路でも密集しすぎる地域は上限に達する場合があります。道路の解析グラフは最大5,000ノード・8,000リンク、接続施設は最大35件です。枠外の迂回路をモデルに含めないため、枠の切り方によって結果は変わります。

## 2. 外部サイトを使わず地域データを準備する

通常の構築ボタンは、利用できる保存済み地域データがあれば自動で再利用し、なければサーバー経由でOverpassへ問い合わせます。新しい大容量の地域ファイルは、容量表示を確認して専用ボタンを押すまで取得しません。Overpassを利用できないとき、または同じ地域で繰り返し範囲を選びたいときは、アプリ内で地域データを準備できます。

1. **アプリ内で地域データを準備する** の **地域とダウンロード量を確認** を押します。この段階では地域名・ファイルサイズなどを確認するだけです。
2. 表示された地域名と容量を確認します。取得する元データは選択した枠より広い地域を含むため、大きなファイルになることがあります。
3. **地域データを取得して構築 / Download regional data and build** を押します。ここで初めて元データのダウンロードが始まります。
4. アプリのサーバーがGeofabrikの公式OSM地域データを保存し、指定した枠を抽出してネットワークを構築します。画面には実際の取得量・処理段階が表示され、中止できます。
5. 同じ保存済み地域の中で枠を選び直せば、通常の構築ボタンからも元データを再利用できます。

**ブラウザで外部サイトへ移動したり、ファイルを自分で保存・読み込みしたりする必要はありません。** 手元にデータがある場合のファイル読込は詳細メニューに残しています。

最初の取得には数分かかることがあります。地域ファイルは最大600 MiBです。画面は十進法のMBで示すため、上限は約629 MBと表示されます。上限を超える地域や対応する元データがない範囲では、この取得方法を利用できません。Overpassの通常取得や別の範囲選択を利用してください。どちらの提供元も外部サービスであり、常に取得できる保証はありません。

## 3. 道路を止め、変化を確認する

1. ネットワーク構築後、地図上の色付き道路を押します。
2. 地図のすぐ上に表示される道路名を確認し、**閉鎖をシミュレーション / Simulate closure** を押します。
3. 閉鎖道路が破線などで区別され、残った道路へモデル交通需要を再配分します。
4. 地図の下の影響パネルで、**経路が変わったODペア数 → 交通が増えた道路 → 指標の前後差** を確認します。
5. 交通が最も増えた道路を表示する操作で、元の閉鎖場所から離れた影響も確認できます。
6. 同じ場所の再開ボタン、または全閉鎖のリセットで元に戻せます。ネットワーク自体を取得し直す必要はありません。

ODペアは「出発地点と目的地の組」です。実際の人数・車両の観測数ではありません。「経路が変わった」には最短経路が変わった組と到達不能になった組を含みます。「交通が増えた道路」は、モデル配分量が平常時より10%を超えて増え、増分が1モデル単位を超える残存道路です。

一部の目的地へ到達できなくなると、道路を走る配分量が減って混雑指標も下がる場合があります。**混雑低下だけを改善と解釈せず、到達不能ODペア・アクセス・レジリエンスも一緒に見てください。** 施設が取得できない分類のアクセスはN/Aとして扱います。

基本の計算結果が出ると次の道路を操作できます。重要道路ランキングは背景で続く場合があります。新しい閉鎖条件の計算を始めた際に、古いランキングを新条件の結果として表示しません。

## 4. 新しい枠と、表示中の結果を区別する

すでにネットワークがある状態で枠だけを動かしても、まだ新しい範囲の分析結果にはなりません。画面には前のネットワークを表示している旨と新しい範囲を構築する操作が出ます。

取得失敗や中止で、前の成功したネットワークを消したり、別都市のデータへ黙って置き換えたりはしません。保存済みOSMサンプルは明示的に選んだときだけ開きます。新しい地域の取得に失敗しても **Demo City** でHarbor Cityを使用できます。

## 5. データと保存先について

| 項目                               | 解釈                                                                                                 |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 道路形状・分類・交差点ID・通行方向 | OpenStreetMapの取込データ                                                                            |
| 施設                               | 対応するOSMタグから取得。地域ファイルではnode・way形式に対応し、relation形式の施設は再構成しません。 |
| 速度                               | 使えるOSM速度タグがあれば利用。なければ道路分類から推定。                                            |
| 車線数                             | 使えるタグがあれば利用。なければ分類ごとの初期値。                                                   |
| 容量                               | モデル上の推定値。実測容量や交通量ではありません。                                                   |
| 交通需要・出発地点の重み           | 合成モデル。人口統計ではありません。広域モードでは一般道路延長を需要の代理値に使います。             |
| 施設接続                           | 350 m以内の近い道路ノードへのモデル接続。実際の入口や安全な経路を保証しません。                      |

Geofabrik経由の場合は提供元とファイル日付を表示します。施設が表示されないことは、現実に施設がないことを意味しません。OSM登録状況・範囲・接続距離・取込形式の制約が影響します。地図とデータには **© OpenStreetMap contributors** の帰属表示を残します。

地域データは**このアプリを動かすサーバー**に保存されます。ローカル起動なら、その起動環境のGit管理対象外のアプリキャッシュです。利用者の現在地を自動取得しません。道路モデルに不要なOSM編集者ID、連絡先、住所タグは抽出結果へ持ち込みません。公開するシナリオ名などにも個人情報を書かないでください。

運用上の上限は次のとおりです。

- 地域データは7日間再利用します。期限後の新規取得では容量確認と明示操作が必要です。
- 完成した地域データは2件まで保持します。置換時に一時的に3件目を取得するため、ファイルだけで最大約1,800 MiBと追加キャッシュの空き容量が必要になる場合があります。
- 新規ダウンロード開始はサーバープロセスごとに1時間2回までです。失敗した開始もこの予算に含みます。
- 地域処理は同時に1件、1処理の上限は280秒です。
- 生成済みネットワークのキャッシュ期間は20分です。

アプリのサーバーを止めると新しい取得はできません。公開ホスティングでは、書込み可能なディスク・保存容量・実行時間が必要です。一時ディスクは再起動などで消えることがあります。短時間のサーバーレス関数へそのまま移して同じ動作になるとは限りません。大人数向けの運用には共有の取得制限・永続キャッシュなどが必要です。保存済みネットワークの再計算と、背景地図タイルの取得は別で、タイルには通信が必要です。

## 6. この改善での確認範囲

以下は最終本番検証と区別した、UI作業中の手動確認記録です。

- 日本語の地図で東京駅付近の座標入力から4.00 km²の開始枠を表示し、四隅操作で6.16 km²へ変更できました。
- 表示中の地図を使う操作で24.80 km²、さらにズームを引いた状態で99.19 km²を選択でき、広域の主要道路表示と構築操作を確認しました。**これは範囲選択の確認であり、その地域の新規データ取得成功を意味しません。**
- 2026年10月10日取得の保存済み松本OSMネットワークで、2道路閉鎖後に表示平均移動時間が2.9分から11.2分、レジリエンスが100から65.9へ変わる操作を確認しました。追加到達不能ODペアは7組、交通が増えた道路は2本でした。施設アクセスは96.0%のままであり、低下したとは扱いません。
- 幅390 pxの表示で横方向のはみ出しを確認し、日本語の操作ラベルを点検しました。端末幅変更後の地図再描画も改善対象としています。
- 変更したUIの対象lint、型チェック、翻訳テストを実行しました。全体の最終テスト数や本番環境の外部取得成功は、この記録から推定しません。

保存済みサンプルの再生、APIを置き換えた自動テスト、新規の外部取得はそれぞれ別の検証です。今回の地域データ取得経路について、最終本番ビルドでの実取得・閉鎖・リセット等の結果は、担当する全体検証記録と照合してください。古い版のテスト数・解析上限を今回の検証結果として使わないでください。
